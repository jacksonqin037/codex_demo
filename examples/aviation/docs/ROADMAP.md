# 开发路线与验收

## 阶段 0：环境与骨架（当前）
Node.js 24、Codex说明、安装和验证脚本、静态构建、CI、ADF+风参数示例。通过启动服务、健康探针与模型测试检查环境。

## 阶段 1：航空实验组件
新增 VOR（OBS、CDI、TO/FROM）、HSI、RMI、风三角和高度表。每类仪表采用独立模块，由真实实验变量驱动刻度和指针。先核对 FAA 等一手资料，明确坐标、角度、单位和信号无效条件。必要时使用教师提供的仪表型号资料，而不是假定外观相同就功能相同。

## 阶段 2：文字描述生成场景
先定义声明式 SceneSpec：实验类别、教学目标、仪表列表、参数（单位/上下限/初值）、台站与飞机位置、运行条件、可交互动作。仅接受经过校验的白名单实验和组件；缺少参数时提示补充；不支持的场景明确说明。规则模板可先用作确定性原型，但必须在 UI 标明支持范围。

若接入语言模型，应由服务端将描述转换为经过校验的 SceneSpec，再由组件注册表渲染；浏览器不执行模型生成的任意代码。模型服务商、密钥与数据策略在接入前确定。模型只配置场景，连续数值仿真由确定性物理引擎完成。

## 阶段 3：实验教学
步骤指引、测量记录、对比实验、故障注入、实验报告导出与教师预设。记录与回放需要保持输入、状态和时间步可复现。

## 验收原则
- 参数改变后，仪表、地图与数字读数一致。
- 角度跨越 0/360、近台/过台、零风和强侧风有明确行为。
- 拖动/点击/旋钮与键盘操作可用；暂停与重置可复现。
- 每种仪表有物理测试与浏览器交互检查，说明教学简化条件。
- 所有代码与图形原创或采用已明确许可的资源，保留来源说明。
